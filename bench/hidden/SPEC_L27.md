### Level 27 — Concurrent Evaluation
`eval_str` must be safe for concurrent use from multiple threads. Independent evaluations must not interfere — each call gets its own environment, and output capture must be isolated per-call. No global mutable state. The interpreter does not need Scheme-level threading primitives; it must simply be reentrant. Tests spawn 4-16 threads calling `eval_str` in parallel with independent computations, closures with `set!` counters, and `display` output capture. Sequential state isolation is also tested: consecutive `eval_str` calls must not share definitions or output buffers.
